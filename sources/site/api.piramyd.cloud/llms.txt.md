\# Piramyd API — Complete Reference for AI Agents > Served at \`https://api.piramyd.cloud/llms.txt\` > For interactive OpenAPI explorer: \`https://api.piramyd.cloud/docs\` Piramyd is an OpenAI-compatible inference gateway that routes text/chat requests to multiple upstream providers. It supports chat completions, responses, Anthropic messages, vision (image input), tool calling, streaming, automatic context compaction, and web intelligence via two self-hosted services: \*\*SIRS\*\* (multi-engine web search) and \*\*CROWD\*\* (URL content extraction). It does \*\*not\*\* currently expose image/video/audio/music \*generation\* endpoints (§7). --- ## 1. They take a \`state\` and a map of typed \`questions\` and return one calibrated answer per question in ~70–500 ms. The body and response are identical to TypeSafe's \`/v1/systemone\`: an existing TypeSafe client only changes its base URL to \`https://api.piramyd.cloud/v1\`. System One models can \*\*only\*\* be called here. Sending one to \`/chat/completions\`, \`/responses\` or \`/messages\` returns \`400\`, and so does sending a chat model to \`/v1/systemone\`. List the valid \`model\` values with \`GET /v1/systemone/models\` (they do not appear in the chat playground). \`\`\`json { "state": "Help! My payouts have been failing for 3 days.", "model": "jev-latest", "questions": { "is\_urgent": {"type": "noul", "instructions": "Does this convey urgency?"}, "department": {"type": "choice", "instructions": "Which team should handle this?", "criteria": {"billing": "Payments, refunds", "technical": "Bugs, outages", "sales": null}}, "frustration": {"type": "score", "instructions": "How frustrated is the customer?", "criteria": \["Calm", "Frustrated", "Very angry"\]} } } \`\`\` | Question | \`criteria\` | Answer | |---|---|---| | \`noul\` (yes/no) | optional \`{"true": ..., "false": ...}\` | \`{"type":"noul","noul":0.95}\` — probability of yes | | \`choice\` | map option → rubric (or \`null\`), 1–255 options | \`choice\`, \`probabilities\`, \`confidence\` | | \`score\` | ordered array of 2–10 levels | \`score\` (can land between levels), \`legend\`, \`probabilities\`, \`confidence\` | \`state\`, \`instructions\` and every rubric may be a string, an object or an array. \`\`\`json { "model": "jev-1.13.0", "answers": { "is\_urgent": {"type": "noul", "noul": 0.95}, "department": {"type": "choice", "choice": "billing", "probabilities": {"billing": 0.88, "technical": 0.12, "sales": 0.0}, "confidence": 0.81} }, "usage": {"input\_tokens": 304, "output\_tokens": 18} } \`\`\` - \`model\` in the response is the \*\*exact version\*\* that answered (\`jev-1.13.0\`), even when you asked for an alias. Pin a version if you calibrate thresholds on \`confidence\`. - \*\*Limits:\*\* 64k tokens per request (state + all questions); 32k for the state plus the longest question. Larger requests get \`413 context\_too\_large\` — shrink the \`state\`, there is no automatic compaction. - \*\*Billing:\*\* input tokens only; output tokens are free. - \*\*No streaming, no tools, no system prompt.\*\* Unknown or hidden models return \`404\` (never a substitute model: a different model would silently shift your thresholds). - Errors: \`422\` invalid question, \`404 model\_not\_found\`, \`403\` tier, \`413\`, \`429\` (retry with backoff, honour \`Retry-After\`), \`503\` provider unavailable. --- ## 7. Media Generation (Not Currently Available) Piramyd's live catalog today is \*\*text/chat models only\*\* (see \`GET /v1/models\`). There is currently \*\*no dedicated image, video, audio, or music generation endpoint\*\* — \`POST /v1/images/generations\`, \`/v1/images/edits\`, \`/v1/videos/generations\`, \`/v1/videos/image-to-video\`, \`/v1/audio/speech\`, \`/v1/audio/transcriptions\`, \`/v1/music/generations\`, and \`GET /v1/tasks/{task\_id}\` \*\*do not exist\*\* and will return \`404\`. Do not call them. Before assuming a capability exists, check a model's \`input\_modalities\` / \`output\_modalities\` / \`capabilities\` from \`GET /v1/models\` — text-in/text-out is the only supported shape right now. \`supports\_vision: true\` means a model can \*read\* images sent in a chat/responses request (§4.4), not generate them. Error Handling ### 10.1 Status Codes | Code | Meaning | Retry? | |------|---------|--------| | 400 | Invalid request payload | No (fix request) | | 401 | Invalid API key or JWT | No (fix credentials) | | 402 | Billing/credit limit reached | No (add credits) | | 403 | Permission denied / tier restriction | No | | 404 | Model or resource not found | No | | 429 | Rate limit (RPM or tokens) | Yes, with backoff | | 500 | Internal server error | Yes, with backoff | | 502 | Upstream provider unavailable | Yes, with backoff | | 503 | Service maintenance | Yes, after delay | | 504 | Request timeout | Yes, with backoff | ### 10.2 Error Response Shape \`\`\`json { "error": { "message": "Rate limit reached. Please wait a few seconds and try again.", "type": "rate\_limit\_error", "code": "rate\_limit\_exceeded", "param": null } } \`\`\` ### 10.3 Streaming Error Shape Errors during streaming arrive as a data event: \`\`\` data: {"error": {"message": "...", "type": "...", "code": "...", "request\_id": "..."}} \`\`\` ### 10.4 Retry Strategy 1. Retry \`429\`, \`502\`, \`503\`, \`504\` with exponential backoff (base 1s, max 8s, jitter). 2. Respect \`Retry-After\` header when present (especially on \`429\`). 3. Do not retry \`400\`, \`401\`, \`403\` without changing the request. 4. For \`context\_length\_exceeded\` errors: the API automatically retries once with context compaction if a \`thread\_id\` is provided. ### 10.5 Access Policy (no free forever tier) There is \*\*no free forever API tier\*\*. Unpaid access is the \*\*Solo 3-day trial\*\* (card required), which maps to the \`trial\` / Solo product path. After the trial, a paid plan is required. Paid tiers use flat monthly pricing with \*\*unlimited tokens\*\*; throughput is governed by RPM (see §16). \`402\` / \`403\` responses indicate billing or access limits — not a weekly free-tier USD budget. --- ## 11. Context Compaction (Automatic) For long conversations that exceed a model's context window, the API automatically compacts earlier messages into a structured summary. This is transparent to the client. \*\*To enable:\*\* Include \`thread\_id\` (or \`conversation\_id\`) in your request: \`\`\`json { "model": "claude-opus-4.8", "messages": \[...\], "thread\_id": "my-conversation-123", "stream": true } \`\`\` The compaction: - Preserves system messages intact - Summarizes older messages into structured sections (goals, plans, decisions, files, tool state, blockers) - Keeps the most recent messages unmodified - Adapts the number of retained messages to the model's context window - Persists checkpoints in Redis for incremental compaction across requests - Activates automatically on \`context\_length\_exceeded\` errors (retry is transparent) - Also applies proactively if a checkpoint exists from a previous request in the same thread --- ## 12. Tool Call Integrity (Automatic) For coding agents that use tool calling with large arguments (e.g. \`write\_file\` with 10KB+ content), the API provides automatic integrity protection during streaming: - \*\*Buffered validation:\*\* Tool call argument deltas are accumulated and only emitted as a single validated chunk - \*\*Auto-repair:\*\* Truncated JSON arguments are deterministically repaired (closing open strings, brackets) - \*\*Continuation:\*\* When the model hits \`max\_tokens\` mid-tool-call (\`finish\_reason: length\`), the API can transparently request continuation This is fully automatic and requires no client-side changes. Clients receive complete, valid tool call JSON. --- ## 13. Compatibility Redirects Non-versioned paths redirect to \`/v1/...\` with HTTP 307 (preserving POST body). Quick Start for AI Agents ### Recommended bootstrap sequence: \`\`\`python import httpx BASE = "https://api.piramyd.cloud/v1" HEADERS = {"Authorization": "Bearer sk-YOUR\_KEY"} # 1. Discover models models = httpx.get(f"{BASE}/models", headers=HEADERS).json() chat\_models = \[m for m in models\["data"\] if "/v1/chat/completions" in m.get("endpoints", \[\])\] tool\_models = \[m for m in chat\_models if m.get("supports\_tools")\] # 2. Pick a model model\_id = tool\_models\[0\]\["id"\] context\_window = tool\_models\[0\]\["context\_length"\] max\_output = tool\_models\[0\]\["max\_output\_tokens"\] # 3. Send inference response = httpx.post(f"{BASE}/chat/completions", headers=HEADERS, json={ "model": model\_id, "messages": \[{"role": "user", "content": "Hello!"}\], "max\_tokens": min(4096, max\_output), "stream": False, }) result = response.json() print(result\["choices"\]\[0\]\["message"\]\["content"\]) \`\`\` ### Key recommendations for agents: 1. \*\*Always discover models dynamically\*\* via \`GET /v1/models\`. Never hardcode model IDs. 2. \*\*Respect \`context\_length\`\*\* from model metadata. Keep your prompt within bounds. 3. \*\*Set \`max\_tokens\`\*\* explicitly. Don't rely on defaults for tool calling with large arguments. 4. \*\*Use \`thread\_id\`\*\* for multi-turn conversations to enable automatic context compaction. 5. \*\*Request \`stream\_options.include\_usage\`\*\* when streaming to get token counts. 6. \*\*Check \`supports\_tools\`\*\* before sending tool definitions — not all models support it. 7. \*\*Handle streaming tool calls\*\* by accumulating \`function.arguments\` fragments before parsing. 8. \*\*Implement retry with backoff\*\* for 429/5xx. The API normalizes upstream errors into consistent shapes. --- ## 15.
